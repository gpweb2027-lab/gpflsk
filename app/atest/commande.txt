Comme tu utilises Windows avec PyCharm pour ton serveur Flask, tu peux vérifier très facilement combien de processus Python font tourner ton jeu Président.

Il faut distinguer deux choses :

Processus : une instance du serveur Python.

Connexions : les joueurs et spectateurs connectés à ton jeu.

Tu peux avoir 30 joueurs connectés sur un seul processus Python.

1. Vérifier les processus sur Windows
Ouvre PowerShell et exécute :

Get-CimInstance Win32_Process |
Where-Object { $_.Name -match "python|gunicorn|waitress" } |
Select-Object ProcessId, ParentProcessId, Name, CommandLine

Tu obtiendras quelque chose comme :

ProcessId  ParentProcessId  Name        CommandLine
--------- ---------------  ----------  ---------------------
1234      800              python.exe  python app.py
5678      1234             python.exe  python app.py
Dans cet exemple, il y a deux processus Python, mais cela ne signifie pas nécessairement qu'ils traitent tous les deux les connexions des joueurs.

Il faut regarder leur commande et leur rôle.

2. Vérifier comment Flask démarre
Regarde la configuration Run / Debug dans PyCharm, ou le terminal dans lequel tu démarres le serveur.

Généralement un processus serveur

flask run --debug

Peut créer deux processus à cause du rechargement automatique

Généralement un processus avec plusieurs threads

gunicorn -w 4 ...

Quatre processus workers, plus un processus maître

Le cas de Flask en mode debug est important : voir deux processus Python ne signifie pas forcément que tu as deux serveurs actifs.

3. Vérifier le processus qui utilise le port de ton jeu
Si ton serveur Flask utilise le port 5000, exécute :

Get-NetTCPConnection -LocalPort 5000 -State Listen |
Select-Object LocalAddress, LocalPort, OwningProcess

Puis, pour identifier le programme :

Get-CimInstance Win32_Process -Filter "ProcessId = 1234" |
Select-Object ProcessId, Name, CommandLine

Remplace 1234 par le numéro obtenu dans la première commande.

Si tu utilises le port 8000 ou un autre port, remplace 5000.

5. Ce que cela change pour ton jeu Président
Si ton application utilise un seul processus serveur Flask, le stockage en mémoire des parties et des présences peut fonctionner dans cette configuration.

Si elle utilise plusieurs processus serveurs, tu risques notamment d'avoir un joueur considéré connecté dans un processus et absent dans un autre, ou une partie disponible dans un processus mais introuvable dans un autre.

run.py démarre sur le port 5000, avec les anciennes routes API.

Nous ajoutons /api/users/messages/recent dans app/users/routes.py.

3. Deux versions différentes

flask routes voit le code récent, mais le serveur déjà démarré utilise encore l'ancienne version chargée en mémoire.

4. Erreur HTTP 404

Le navigateur appelle la nouvelle route, mais l'ancien serveur ne la connaît pas.

Redémarrage complet → API fonctionnelle

La confirmation la plus forte, c'est que nous n'avons pas eu besoin de modifier le code pour résoudre l'erreur. Il a suffi de redémarrer le bon processus.

2. Comment éviter ce problème à l'avenir
Je te recommande de prendre ces quatre habitudes.

1. Redémarrer Flask après toute modification Python

Quand nous modifions routes.py, models.py, __init__.py ou un autre fichier backend, arrête complètement le serveur avant de le relancer.

Le rechargement automatique de Flask est pratique, mais il ne faut pas toujours compter dessus.

2. Vérifier qu'un seul serveur utilise le port 5000

Dans PowerShell :

Get-NetTCPConnection -LocalPort 5000 -State Listen -ErrorAction SilentlyContinue |
    Select-Object LocalAddress, LocalPort, OwningProcess

Tu dois normalement voir un seul processus à l'écoute sur ce port.

3. Vérifier l'identité du processus

Si tu as un doute :

Get-CimInstance Win32_Process -Filter "ProcessId = 5100" |
    Select-Object ProcessId, Name, CommandLine

Remplace 5100 par le PID affiché par la commande précédente.

Cela permet de vérifier quel fichier Python est réellement exécuté.
